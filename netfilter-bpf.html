读图时不能省略的区别

  • 本机流量不经过 FORWARD。本机接收是 PREROUTING → INPUT，本机发送是 OUTPUT → POSTROUTING；路由转发才是 PREROUTING → FORWARD → POSTROUTING。
  • BPF 并不是单一 hook。XDP、TC/TCX、cgroup_skb、socket filter、sock_addr、sock_ops、sk_msg/sk_skb 具有不同上下文和触发条件。现代 XDP/TC-BPF/cgroup-BPF 不能倒推为旧 2.x 内核已有功能。
  • socket 过滤点：tcp_filter() → sk_filter_trim_cap() 中先执行 cgroup ingress，再执行安全检查和 socket filter。TCP 状态机、backlog 和监听连接走不同分支。
  • cgroup egress：v6.6 的 ip_finish_output() 在 POSTROUTING 之后调用它；它需要合适的 socket/cgroup 上下文，不是转发包通用过滤点。
  • TC egress 在 qdisc 入队前。v6.6 的 __dev_queue_xmit() 中，nft netdev egress 又位于 TC egress 之前。不要把 TC egress 画到出队和驱动之间。
  • 命名空间：“host”是部署环境中的宿主网络 namespace（通常为 initial netns），并不是特殊协议栈；Netfilter 配置属于 netns，TC/XDP 挂在具体设备，cgroup BPF 属于 cgroup，不能把它们统称为 host 全局规则。
  • 不展开：IPv6、bridge/ARP、veth/容器跨 namespace、隧道、IPsec/XFRM、硬件 offload、全部 SYN/FIN/RST/重传状态机、锁和内存分配内部函数。ACK、定时器和重传可直接进入较低层发送路径，不一定从 sendmsg 起步。

security 是额外的第五张可选表，INPUT/FORWARD/OUTPUT 优先级 +50，图中以方括号显示。INPUT 的 nat 链在较新内核中存在（自 2.6.36），不能套用于更早的所有 2.x 版本。

conntrack 不是一张 iptables 表：IPv4 defrag 通常是 -400，连接跟踪是 -200，连接确认在 INPUT/POSTROUTING 的 INT_MAX。NOTRACK 可以使流量不被跟踪。图中省略部分 SELinux、helper 等专用回调；数字不表示每个 hook 都注册了全部这些回调。

NAT 是有状态映射，不是每包重新匹配 NAT 规则：通常连接首包匹配规则以创建映射，后续包由 conntrack/NAT 在相应 hook 应用映射。DNAT 后会影响路由选择，OUTPUT 修改地址或 mark 也可能触发重新路由。

hook 内部如何执行规则？

IPv4 调用 NF_HOOK / nf_hook() 后，由 nf_hook_slow() 按优先级遍历注册的回调。legacy filter/mangle/raw 的表回调进入 ipt_do_table()；legacy NAT 通过 NAT 核心在需要建立映射时调用表规则。原生 nft base chain 则进入 nft_do_chain()（可能通过类型或 family 包装函数）。它们是同一 hook 内的不同处理器，图中表名是策略位置，不是函数名。

nftables 在图中怎么定位？

IPv4 的原生 nft base chain 可注册到相同的 PREROUTING、INPUT、FORWARD、OUTPUT、POSTROUTING hook。例如 type filter hook input priority 0 与 legacy filter INPUT 处于相同阶段；表叫 filter 并不赋予它过滤语义，真正决定执行位置的是链的 type、hook 和 priority。

nft 的 netdev ingress（以及现代内核的 inet ingress）是入站设备级 hook，在 TC ingress 后、IPv4 PREROUTING 前；netdev egress 在 TC egress 前。它们不属于 iptables 五链。netdev ingress 早于 IPv4 defrag/conntrack，不能默认认为它已有完整 conntrack 上下文。

共存与 verdict

  • iptables-legacy 与 nf_tables 可同时注册在同一 Netfilter hook；不是“先完整走完 iptables，再完整走 nft”。按所有注册回调的优先级执行，相同优先级不要依赖顺序。
  • 某个 base chain 中的 accept 只结束该链的检查，后续 base chain/hook 仍可丢包；drop 则终止当前报文的继续处理。
  • Linux 4.18+ 支持 legacy NAT 与 nft NAT 共存，但首个建立 NAT 映射的匹配规则决定映射。不要把同一策略同时交给两套管理器维护。
  • 用 iptables -V 识别 (legacy) 或 (nf_tables)；nft list ruleset 不能显示 legacy 规则。排查时要同时确认后端和 namespace。

图里没有串到主线上的 BPF

BPF_PROG_TYPE_NETFILTER 自 Linux 6.4 起支持直接附着 Netfilter hook，v6.6 也有：它按附着时指定的 hook/priority 参与回调排序，不是固定的第六条链。它与 XDP、TC 和 socket BPF 不同。图中橙色 hook 的内部可包含这类 BPF 回调；未把它画在表链之外以免误导为额外的必经阶段。
